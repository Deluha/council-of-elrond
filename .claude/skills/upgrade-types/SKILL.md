# Upgrade the vendored types

`mods/types/claude-code.d.ts` is the source of truth for the plugin API, ahead of docs and the
spec. It is generated by Claude Code and must match the version users run. Procedure:

## 1. Compare versions

```sh
claude --version
head -12 mods/council-of-elrond/DESIGN.md | grep -i "targets claude code"
```

If they match, stop: nothing to do.

## 2. Regenerate

Load the `plugin-authoring` skill (it ships with Claude Code). It writes a fresh
`types/claude-code.d.ts` under the skill's own folder and prints the path. **Do not point it at
`mods/council-of-elrond`**: writing into a mod folder makes it offer to hot-reload that mod into
this session, which would gate your own tool calls.

Copy the generated file over `mods/types/claude-code.d.ts`.

## 3. Measure the drift

```sh
git diff --stat mods/types/claude-code.d.ts
git diff mods/types/claude-code.d.ts | grep '^[-+]' | grep -v '^[-+][-+]' | grep -v '^\s*[-+]\s*\*' | head -200
```

Then for every method in DESIGN.md §2's `calls:` line (`$.clock.after`, `$.fs.read`,
`$.model.complete`, `$.process.spawn`, `$.ui.ask`, …) grep the new file and confirm the signature
the mod relies on is unchanged. Classify the drift: **additive** (nothing the mod calls changed),
**changed** (a signature the mod uses moved), or **removed**.

## 4. Gates

```sh
tsc -p mods
claude plugin test mods/council-of-elrond
claude plugin validate mods/council-of-elrond
```

A `tsc` failure is the drift talking. Fix the mod to the new API; never edit the generated file.

## 5. Re-verify the binary's wording

The mod tells a user's refusal at the permission prompt from an ordinary tool error by wording
read from the binary (DESIGN.md §6.14; `outcomeOf` in `hooks/elrond/operations.ts`).

```sh
BIN=$(readlink -f "$(command -v claude)")
grep -a -o "The user doesn't want to [a-z ]*" "$BIN" | sort -u
grep -a -o -E "[a-z ]*(needs|requires) approval[^\"]{0,80}" "$BIN" | sort -u | head
grep -a -o -E "requested permissions? to (use|write|edit|read|run)[^\"]{0,80}|haven't granted it yet[^\"]{0,40}|permission to use [^\"]{0,60} has been denied" "$BIN" | sort -u | head
```

The patterns to compare against are `USER_REFUSAL` and `AUTOMATIC_DENIAL` in
`hooks/elrond/operations.ts`. A wording the binary has that no pattern matches reads as an
ordinary tool error and counts as a failed attempt: add it to the right list with a test
(`tests/operations.test.ts › outcomes`).

If the phrases changed, update the patterns and `tests/operations.test.ts`, and run one headless
probe (see the `live-check` skill) that refuses in `-p` to confirm the automatic-denial text.

## 6. Re-probe behaviours the tests can't see

One headless probe each, in a throwaway repo, for the facts in DESIGN.md §1 and §4 that came from
live probes: a hook overrunning its budget still runs `next(e)`; `$.ui.ask` rejects in `-p`;
`stream.return()` kills a spawned check; `/council` output arrives as `ui_log` in stream-json.
Skip any whose cost outweighs the risk, and say which you skipped.

## 7. Record

- DESIGN.md header: the new version and the drift in one sentence.
- ROADMAP.md "Resuming": the version line.
- CHANGELOG.md "Unreleased": "Types regenerated for Claude Code X.Y.Z; drift: …".
- CI (`.github/workflows/ci.yml`): if it was pinned to the old version, unpin or move the pin.
