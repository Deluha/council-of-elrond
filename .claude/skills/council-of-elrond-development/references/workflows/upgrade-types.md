# Upgrade the vendored types to a new Claude Code build

## Preconditions

`mods/types/claude-code.d.ts` is the source of truth for the plugin API, ahead of docs and the
spec. It is generated by Claude Code and must match the version users run.

Use it monthly and before a release (ROADMAP decision D10), not whenever `claude --version` differs from the version at the top of DESIGN.md; CI stays on its pin until this procedure moves it. CI is pinned to the version at the top of DESIGN.md, and a scheduled job on the latest build reports drift. A newer release that breaks the vendored types before you have time to upgrade changes nothing for CI, which stays on the pin; open an issue.

Compare the versions:

```sh
claude --version
head -12 mods/council-of-elrond/DESIGN.md | grep -i "targets claude code"
```

If they match, stop: nothing to do. If the installed build is newer and no upgrade is due (not
monthly, not before a release), stop too: a newer build is expected and is not a reason to upgrade
mid-brief.

Replacing `mods/types/claude-code.d.ts` is refused today by the deny rule in `.claude/settings.json` (probed on 2.1.322: the rule also refuses a shell copy). This step needs the maintainer: ask before starting, and never remove or edit the rule yourself. The maintainer's decision on whether the rule becomes an ask rule is recorded as an open decision in the roadmap (OD25).

## Steps

### Regenerate

Load the `plugin-authoring` skill (it ships with Claude Code). It writes a fresh
types/claude-code.d.ts under the skill's own folder and prints the path. **Do not point it at
`mods/council-of-elrond`**: writing into a mod folder makes it offer to hot-reload that mod into
this session, which would gate your own tool calls.

Copy the generated file over `mods/types/claude-code.d.ts` once the maintainer has agreed (see Preconditions: the deny rule refuses the copy today). Re-check that probe on each upgrade.

### Measure the drift

```sh
git diff --stat mods/types/claude-code.d.ts
git diff mods/types/claude-code.d.ts | grep '^[-+]' | grep -v '^[-+][-+]' | grep -v '^\s*[-+]\s*\*' | head -200
```

Then for every method in DESIGN.md §2's `calls:` line (`$.clock.after`, `$.fs.read`,
`$.model.complete`, `$.process.spawn`, `$.ui.ask`, …) grep the new file and confirm the signature
the mod relies on is unchanged. Classify the drift: **additive** (nothing the mod calls changed),
**changed** (a signature the mod uses moved), or **removed**.

### Run the gates on the new build

Run them on the build you are upgrading to. Point `COUNCIL_CLAUDE` at that **new** build (or
unset it if the new build is the installed `claude`): left pointing at the old pin, the gates
would run on the old build. The pre-commit hook refuses a build other than the pin unless
`COUNCIL_ALLOW_UNPINNED=1`; set it for this brief only. The full explanation is in
`references/qa-and-ci.md` (The pinned build).

```sh
tsc -p mods
"${COUNCIL_CLAUDE:-claude}" plugin test mods/council-of-elrond
"${COUNCIL_CLAUDE:-claude}" plugin validate --strict mods/council-of-elrond
```

A `tsc` failure is the drift talking. Fix the mod to the new API; never edit the generated file.

### Re-verify the binary's wording

The mod tells a user's refusal at the permission prompt from an ordinary tool error by wording
read from the binary (DESIGN.md §6.14; `outcomeOf` in `hooks/elrond/operations.ts`).

```sh
BIN=$(readlink -f "$(command -v "${COUNCIL_CLAUDE:-claude}")")
grep -a -o "The user doesn't want to [a-z ]*" "$BIN" | sort -u
grep -a -o -E "[a-z ]*(needs|requires) approval[^\"]{0,80}" "$BIN" | sort -u | head
grep -a -o -E "requested permissions? to (use|write|edit|read|run)[^\"]{0,80}|haven't granted it yet[^\"]{0,40}|Permission to (use|edit|read) [^\"]{0,60} has been denied|Permission for this tool use was denied[^\"]{0,60}" "$BIN" | sort -u | head
```

The patterns to compare against are `USER_REFUSAL` and `AUTOMATIC_DENIAL` in
`hooks/elrond/operations.ts`. A wording the binary has that no pattern matches reads as an
ordinary tool error and counts as a failed attempt: add it to the right list with a test
(`tests/operations.test.ts › outcomes`).

If the phrases changed, update the patterns and `tests/operations.test.ts`, and run one headless
probe (see `references/workflows/live-check.md`) that refuses in `-p` to confirm the automatic-denial text.

### Re-probe behaviours the tests can't see

One headless probe each, in a throwaway repo, for the facts in DESIGN.md §1 and §4 that came from
live probes: a hook overrunning its budget is cut off (from 2.1.299: its `.catch` is asked with
`kind` `timeout`, a later `next(e)` is refused and the call is refused); `$.ui.ask` rejects in `-p`;
`stream.return()` kills a spawned check; `/council` output arrives as `ui_log` in stream-json.
Skip any whose cost outweighs the risk, and say which you skipped. Brief M0.4 turns this into a script.

### Re-check whether `$.fs` has an append

The audit appender reads and rewrites the whole file for each line because the types have no
append for files (finding A7). Search the new `mods/types/claude-code.d.ts` for a file append on
`$.fs`. If one exists, say so in the record below and open a brief to use it; if not, say that it
still has none. (`session.append` in the types is a different call.)

## Verification

The gates above pass on the new build (`tsc -p mods`, the tests, `claude plugin validate --strict mods/council-of-elrond`), then `node scripts/verify.mjs --all` on the new build with `COUNCIL_ALLOW_UNPINNED=1` for this brief only (`references/qa-and-ci.md`). `git diff --stat` shows `mods/types/claude-code.d.ts` replaced by the generated file, never edited by hand. The drift is classified (additive, changed or removed) and written down.

## Ask first

- **The vendored types** (`mods/types/claude-code.d.ts`): a hand edit is denied; replace the file by a copy of the generated one, never an edit (R2). The copy is refused today too: stop and ask the maintainer (Preconditions).
- **The CI pin and the workflows** (`.github/`): path-gated, the edit prompts; the pin moves only in an upgrade brief. Confirm the maintainer action about pushing workflow files first (MA9).
- **The denial wordings** (`hooks/elrond/operations.ts`), if the binary's text changed: stop and ask.
- **The release heading and the version**: not at an upgrade.
